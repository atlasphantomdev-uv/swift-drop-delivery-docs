# Contributing to the documentation

Thank you for helping improve the public Swift Drop technical documentation.

## Good contributions

- Correcting an inaccurate public behavior description
- Improving clarity for developers or integration partners
- Adding a safe architecture explanation
- Fixing a broken link or confusing URL example

## Do not submit

- Production source code or deployment files
- API keys, passwords, webhook secrets, or environment files
- Customer names, addresses, phone numbers, order references, or screenshots
- Unverified claims about prices, ratings, delivery times, coverage, or payment methods
- Keyword-stuffed pages or links created only to influence rankings

Open a pull request with a short explanation of the change and the public behavior it
documents. For private security concerns, use the [contact page](https://swiftdrop.express/contact)
instead of publishing details in an issue.
